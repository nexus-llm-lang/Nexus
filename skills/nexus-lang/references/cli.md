## Subcommands

### `nexus build`

**Synopsis**

    nexus build <input.nx> [-o <output.wasm>] [--coverage] [--profile-out FILE]

Compile a Nexus source file to a self-contained WebAssembly module.
The full pipeline runs (parse, resolve, HIR/MIR/LIR, codegen, link, merge) and
the resulting wasm is written to the path given by -o (default: out.wasm).

Run the resulting module directly with wasmtime, e.g.
  wasmtime run -W tail-call=y,exceptions=y,function-references=y,stack-switching=y,threads=y --dir=. out.wasm
Determinism hooks are read from the environment at runtime:
  --env NEXUS_SEED=N            fixed RNG seed
  --env NEXUS_FROZEN_CLOCK=EPOCH_MS  pinned wall/mono clock.

**Flags**

| Flag | Description |
| ---- | ----------- |
| `-o, --output VALUE` | output wasm path (default: out.wasm) |
| `--coverage` | emit coverage counters and custom section |
| `--profile-out VALUE` | write per-call-site profile JSONL to FILE (static const-arg analysis) |
| `--dump-imports` | print the import graph and exit |
| `--verbose` | enable per-pass timing output |
| `--format VALUE` | diagnostic format (text|json) |
| `--explain-capabilities VALUE` | capability reporting (yes|none|wasmtime) |
| `--explain-capabilities-format VALUE` | capability report format (text|json) |
| `--no-lint` | skip the lint pass after typecheck |
| `--lint-level VALUE` | lint finding severity on build (warn|error); default error gates the build, warn opts out |
| `--deny VALUE` | promote named lint rule codes to build-gating errors (comma-separated, e.g. L0002) |

**Examples**

- `nexus build examples/hello.nx -o hello.wasm` — compile a single source file to a wasm module
- `nexus build src/main.nx -o nexus.wasm` — compile the compiler to a core wasm module
- `nexus build foo.nx --coverage -o foo.cov.wasm` — instrument with coverage counters
- `nexus build src/main.nx --profile-out profile.jsonl` — emit per-call-site const-arg profile

**See also**: `nexus typecheck`, `nexus test`

**Exit codes**

| Code | Meaning |
| ---- | ------- |
| 0 | success |
| 1 | compilation or runtime failure (diagnostic on stderr) |
| 2 | invalid CLI usage (E4002 / E4004) |

### `nexus types`

**Synopsis**

    nexus types <input.nx> [--transitive] [--format text|json]

Dump <input.nx>'s own top-level bindings' inferred types after full
typechecking. By default the output is scoped to symbols defined in
<input.nx> and identifiers appear as bare names. Pass --transitive
to include imported symbols too; imported identifiers render in the
module-path form used by import statements (e.g. `std:str.load_at`).
With --format json the output is keyed by symbol and includes effect
rows, which is the canonical input to editor hover/`explain` flows.

**Flags**

| Flag | Description |
| ---- | ----------- |
| `--format VALUE` | output format (text|json) |
| `--transitive VALUE` | include types for symbols imported from other files |
| `--verbose` | enable per-pass timing output |
| `--format VALUE` | diagnostic format (text|json) |
| `--explain-capabilities VALUE` | capability reporting (yes|none|wasmtime) |
| `--explain-capabilities-format VALUE` | capability report format (text|json) |
| `--no-lint` | skip the lint pass after typecheck |
| `--lint-level VALUE` | lint finding severity on build (warn|error); default error gates the build, warn opts out |
| `--deny VALUE` | promote named lint rule codes to build-gating errors (comma-separated, e.g. L0002) |

**Examples**

- `nexus types foo.nx` — text dump of foo.nx's own bindings (bare names)
- `nexus types foo.nx --transitive` — include imported symbols (rendered as std:str.load_at etc.)
- `nexus types src/main.nx --format json` — JSON for editor integration

**See also**: `nexus typecheck`, `nexus explain`

**Exit codes**

### `nexus caps`

**Synopsis**

    nexus caps <symbol> <input.nx> [--format text|json]

Dump the transitive capability closure of one named function: every
capability (Fs / Net / Console / Random / Clock / Proc / Env) reached
by any function transitively called from <symbol>. Useful for agents
or reviewers asking 'does this function touch the filesystem?' before
an edit. Symbol resolution accepts either the canonical qualified form
(`<sanitized_path>#<name>`) or the bare suffix.

**Flags**

| Flag | Description |
| ---- | ----------- |
| `--format VALUE` | output format (text|json) |
| `--verbose` | enable per-pass timing output |
| `--format VALUE` | diagnostic format (text|json) |
| `--explain-capabilities VALUE` | capability reporting (yes|none|wasmtime) |
| `--explain-capabilities-format VALUE` | capability report format (text|json) |
| `--no-lint` | skip the lint pass after typecheck |
| `--lint-level VALUE` | lint finding severity on build (warn|error); default error gates the build, warn opts out |
| `--deny VALUE` | promote named lint rule codes to build-gating errors (comma-separated, e.g. L0002) |

**Examples**

- `nexus caps main src/main.nx` — caps reached from driver's main
- `nexus caps lint_file src/tools/lint.nx --format json` — JSON dump of a library symbol

**See also**: `nexus explain`, `nexus types`

**Exit codes**

| Code | Meaning |
| ---- | ------- |
| 0 | symbol resolved and closure printed |
| 1 | symbol not found in the named file |
| 2 | invalid CLI usage (E4002 / E4004) |

### `nexus bench`

**Synopsis**

    nexus bench [--dir DIR] [--iters N] [--nexus-bin PATH] [--wasmtime-bin PATH] [--baseline PATH]

Run every `bench_*.nx` under DIR (default `examples/feature/`). Each bench
must print a single integer (milliseconds) as its last stdout line. The
runner executes each bench N times (default 5), computes median and p95,
and emits one NDJSON line per bench to stdout:
  {"name":"arith","median_ms":42,"p95_ms":45,"iters":5}

With --baseline PATH the runner reads the baseline JSON array and fails
(exit 3) if any bench's median_ms drifts more than ±20% from its
corresponding baseline entry.

WASI threads note: bench files in the suite use sequential code only.
Parallel-thunk benches are inherently noisy across hardware and should
live outside this discovery prefix.

**Flags**

| Flag | Description |
| ---- | ----------- |
| `--dir VALUE` | bench discovery directory (default: examples/feature/) |
| `--iters VALUE` | iterations per bench (default: 5) |
| `--nexus-bin VALUE` | path to the nexus binary (default: ./nexus) |
| `--wasmtime-bin VALUE` | path to the wasmtime binary (default: wasmtime) |
| `--baseline VALUE` | baseline JSON path; exit 3 if any bench drifts >±20% |

**Examples**

- `nexus bench` — run all bench_*.nx under examples/feature/
- `nexus bench --iters 10` — 10 iterations per bench
- `nexus bench --baseline bench-baseline.json` — gate on ±20% drift from baseline

**See also**: `nexus test`, `nexus build`

**Exit codes**

| Code | Meaning |
| ---- | ------- |
| 0 | all benches ran (and baseline check passed) |
| 1 | at least one bench failed to compile or run |
| 2 | invalid CLI usage |
| 3 | baseline drift gate: at least one bench exceeded ±20% |

### `nexus grep`

**Synopsis**

    nexus grep <pattern> [<path>...]

Search `.nx` source files for AST nodes matching a pattern.
Pattern syntax: `[<kind>] <name>` where kind is one of `let`, `fn`,
`call`, or `var` (default: `call`), and name is a literal identifier
or a `$`-prefixed wildcard (e.g. `$_` matches any name).
Paths default to the current directory; directories are searched
recursively for `.nx` files.

**Flags**

(none)

**Examples**

- `nexus grep 'let helper' src/` — find the let-binding named 'helper' under src/
- `nexus grep 'fn $_' src/` — find every fn binding in src/
- `nexus grep 'call Fs.open_read' src/` — find every call to Fs.open_read
- `nexus grep 'var $_' src/main.nx` — find every variable reference in one file

**See also**: `nexus ast`

**Exit codes**

| Code | Meaning |
| ---- | ------- |
| 0 | at least one match was found |
| 1 | no matches |
| 2 | invalid pattern or CLI usage |


### `nexus lint`

**Synopsis**

    nexus lint [--check|--fix|--fix-diff] FILE [FILE...]

Run the Nexus linter over the given source files. Reports style and
correctness issues as L-code findings. With --check the exit code is
non-zero on any finding.

Auto-fix modes (the heavier front-end is only engaged in these modes;
plain lint and --check remain AST-only and fast):
  --fix       apply lint-rule fix-its in place, looping to a fixpoint, then
              run the front-end; a remaining compiler error is printed
              and the exit code is non-zero.
  --fix-diff  show a before/after diff for every fix-it without writing.

See also: `nexus fmt` for whitespace normalisation (separate concern).

**Flags**

| Flag | Description |
| ---- | ----------- |
| `--check` | exit non-zero on any finding (CI mode) |
| `--fix` | apply lint-rule fix-its in place (loops to fixpoint) |
| `--fix-diff` | show before/after diff without writing |

**Examples**

- `nexus lint src/main.nx` — lint a single file
- `nexus lint --check src/` — CI gate — fails on any finding
- `nexus lint --fix src/main.nx` — apply all fix-its in main.nx in place
- `nexus lint --fix-diff src/main.nx` — preview fix-its without modifying files

**See also**: `nexus fmt`

**Exit codes**

| Code | Meaning |
| ---- | ------- |
| 0 | no findings (or findings accepted / all fix-its applied) |
| 1 | --check: at least one finding; --fix: non-fixable error |
| 2 | invalid CLI usage |


### `nexus skill`

**Synopsis**

    nexus skill --emit [--out PATH] | --check [--out PATH]

Auto-regenerate the CLI-reference markdown from the compiler's
authoritative spec tables (`subcommand_specs()` / `global_help_specs()`
in src/cli/specs.nx). The intent is to keep the LLM context harness
(skills/nexus-lang, AGENTS.md) in lockstep with the actual subcommand
and flag inventory — handy when adding or renaming a subcommand.

Default output path: skills/nexus-lang/references/cli.md. With --check the on-disk
file is read and compared against the freshly-rendered output; mismatch
exits 1 (suitable as a CI gate).

**Flags**

| Flag | Description |
| ---- | ----------- |
| `--emit` | regenerate the CLI-reference document (default action) |
| `--check` | verify the on-disk file matches; exit 1 on drift |
| `--out VALUE` | output path (default: skills/nexus-lang/references/cli.md) |

**Examples**

- `nexus skill --emit` — regenerate skills/nexus-lang/references/cli.md from compiler state
- `nexus skill --emit --out cli.md` — write to a different path
- `nexus skill --check` — CI gate — exits 1 if skills/nexus-lang/references/cli.md is stale

**See also**: `nexus help`, `nexus explain`

**Exit codes**

| Code | Meaning |
| ---- | ------- |
| 0 | emitted successfully or --check matched |
| 1 | --check detected drift, or write/read failed |
| 2 | invalid CLI usage |
